# 顶底区域与信号评测实施计划

状态：阶段 A/B 已实现并生成 `top_bottom_regions_v2`；下一步从阶段 C 的统一事件流与区域匹配器继续。信号候选清单不在本页扩展。

## 目标与任务边界

核心问题是：一个严格点时、可因果生成的信号，能否提前预测或在短期内确认指数顶部、底部。

工作拆成两个任务：

1. **顶底区域识别**：使用完整历史行情生成事后标准答案，允许使用未来数据。
2. **两套离线评测**：分别评价区域定位和信号后 5/10/20 日结果。评分器可以读取未来标签与结果，但送入评分器的信号必须在每个日期严格因果。

未来数据的边界是“不能参与信号生成”，不是“评分器不能读取未来答案”。任何日期 `t` 的信号，在把 `t` 之后行情截掉后都应保持不变；区域标签和未来结果则允许随样本终点变化。

本阶段不做交易规则、仓位、手续费、收益回测、多个信号组合或统一总分。

## 当前基线与已知缺口

现有 [`../labels.py`](../labels.py) 以日 K 高低价生成小/中/大三级 directional-change 点。中级点负责宏观转折，小级点可提供局部峰瓣，但当前评分只围绕单个锚点及其前置窗口：

- V 型顶底通常能命中；
- W 底、M 顶和平台顶底可能被拆散或漏掉部分峰瓣；
- 极值附近的相近价格没有形成区域；
- 极值后的有效信号没有独立记为“确认”；
- 连续信号的首发、持续和确认语义没有统一。

上证指数 2021 年是固定真实样例：中级顶部锚点为 `2021-02-18`、`2021-06-02`、`2021-09-14`，事后 directional-change 确认分别滞后 12、39、88 个交易日。新版应保留三个独立宏观顶部区域，同时允许每个区域包含一个或多个顶部峰瓣。

## 已冻结协议（阶段 A）

| 参数 | V1 值 | 含义 |
| --- | --- | --- |
| `label_version` | `top_bottom_regions_v2` | 区域、峰瓣和 manifest 的版本 |
| `price_band_fraction_of_threshold` | `0.20` | 候选价格带为各指数中级反转阈值的 1/5 |
| `max_price_band_pct` | `0.02` | 价格带绝对上限为 2%，避免高波动指数纳入偏离较大的峰瓣 |
| `max_side_days` | `20` | 规范锚点左右最多各搜索 20 个交易日 |
| `max_lobe_gap` | `10` | 两个近极值片段之间最多允许 10 个非核心交易日 |
| 时间分区 | 相邻锚点中点 | 每个中级锚点拥有不重叠的最近时间单元，避免顶区和底区重叠 |
| 预测窗口 | `5/10/20` | 阶段 C/D 分别报告 |
| 确认窗口 | `5/10/20` | 5 日主口径、10 日辅助、20 日延迟诊断 |
| `capped_confirmation_n` | `2` | 阶段 C 的连续信号因果确认上限 |

参数来自指数形态审计和合成 V/W/M/平台样例，未读取候选信号成绩。协议由 [`../regions.py`](../regions.py) 的冻结 dataclass 定义，并完整写入区域 manifest；变更任一值必须使用新 `label_version`，不得覆盖既有版本。

## 一、事后顶底区域

### 1. 分层表示

保留中级 directional-change 点作为规范锚点和宏观分段，不直接用信号结果改写。区域采用两层表示：

- **核心峰瓣（core lobes）**：时间上连续、价格接近规范极值的一个或多个片段；M 顶/W 底由多个峰瓣表达。
- **完整包络（envelope）**：从首个核心峰瓣开始到最后一个核心峰瓣结束的连续时间区间，用于宽松定位；峰瓣之间的回撤或反弹仍属于同一形态的内部路径。

`price_band_pct = min(medium_threshold * 0.20, 0.02)`。顶部价格接近度以 `high >= anchor_price * (1 - price_band_pct)` 判断，底部对称使用 `low <= anchor_price * (1 + price_band_pct)`。核心峰瓣是满足价格条件的连续交易日片段；相邻小级同类极值只记录为诊断信息，不参与 V2 峰瓣准入或合并。

### 2. 构造步骤

对每个指数、每个合格中级锚点依次执行：

1. 在相邻中级反向锚点之间按交易日位置中点分区，使每个锚点拥有不重叠的时间单元；
2. 在锚点左右各 `max_side_days` 个交易日内搜索近极值日期，并受宏观分段边界裁剪；
3. 按冻结的价格带提取连续核心峰瓣，记录每瓣代表极值、起止日和价格差；
4. 仅当峰瓣间隔不超过 `max_lobe_gap` 且中间没有中级反向锚点时合并为同一区域；
5. 以首、末峰瓣形成完整包络，规范锚点仍使用原中级点；
6. 保留 directional-change 的事后确认日，只作为标签属性，不作为区域终点或信号日期。

V2 已冻结 `price_band_pct = min(medium_threshold * 0.20, 0.02)`、`max_side_days = 20`、`max_lobe_gap = 10`。不同指数通过既有中级阈值倍率获得 1.6%—2.0% 的价格带，不再逐指数调参。

### 3. 已实现输出

[`../artifacts/regions/top_bottom_regions_v2/turning_point_regions.csv`](../artifacts/regions/top_bottom_regions_v2/turning_point_regions.csv) 一行一个宏观区域：

| 字段 | 含义 |
| --- | --- |
| `region_id` / `index_id` / `event_type` / `scale` | 稳定 ID、指数、顶/底、标签层级 |
| `region_start` / `region_end` | 完整包络起止日 |
| `anchor_date` / `anchor_price` | 中级 directional-change 规范极值 |
| `first_core_date` / `last_core_date` | 首、末核心峰瓣边界 |
| `lobe_count` | 核心峰瓣数量；大于 1 表示 M/W 或多峰平台 |
| `confirmation_date` / `confirmation_lag` | 事后反转确认信息 |
| `threshold` / `price_band_pct` / `price_band_fraction_of_threshold` / `max_price_band_pct` / `label_version` | 可复现参数和版本 |

## 二、严格因果的信号事件

每个候选信号先保留逐日 `raw_value` 和 `triggered`，再派生事件，不能只存筛选后的命中日期。

| 事件 | 日期语义 | 用途 |
| --- | --- | --- |
| `onset` | 连续触发段第 1 个活跃日 | 最早预警、预测能力主口径 |
| `continuation` | 同段其余活跃日 | 持续性诊断，不当作独立报警堆叠 |
| `exit` | 活跃段结束后的第 1 个非活跃日 | 失败与短段结束诊断 |
| `capped_confirmation(N)` | 长段第 N 个活跃日；不足 N 日的短段在退出日 | 有限等待的因果确认口径 |

当 `N=2`，原序列 `0,1,0,1,1,1` 的 onset 为 `0,1,0,1,0,0`，capped confirmation 为 `0,0,1,0,1,0`。短段只有在看到退出日后才确认；样本末尾尚未退出且不足 N 日的段记为未决，不能回填最后活跃日。

计划输出：

- `signal_daily.csv`：逐日原始值、触发状态、数据质量和口径版本；
- `signal_episodes.csv`：episode 起止、长度、onset、exit、各 N 的因果确认日期；
- 每种事件流单独评分，onset 与 capped confirmation 不互相替代。

因果性回归采用“截断不变性”：任取日期 `t`，分别用截至 `t` 和完整样本生成信号，`t` 及以前的值、状态和已产生事件必须完全一致。

## 三、评测 A：顶底区域定位

### 1. 匹配规则

顶部信号只与顶部区域匹配，底部同理。以 signal episode 的指定事件日期和宏观区域做一对一主匹配：一个 episode 最多匹配一个区域，一个区域最多接受一个主 episode。

候选匹配按以下固定优先级选择：核心峰瓣命中、完整包络命中、包络外但在冻结的预测/确认窗口内；同级再选择与规范锚点绝对间隔最小者，最后用稳定 ID 打破并列。落入已匹配区域的额外 episode 记为重复报警，不静默删除。

相对规范锚点的事件日分类：

- `event_date <= anchor_date`：预测，分别报告提前 5/10/20 个交易日窗口；
- `event_date > anchor_date`：确认，5 日为主、10 日为辅、20 日仅作延迟诊断；
- 超出冻结窗口：不算命中，即使事后位于很长的 directional-change 确认区间。

核心峰瓣为严格口径，完整包络为宽松口径，两者分别报告。不能因为使用区域就取消相对规范极值的 lead/lag。

### 2. 指标

顶部、底部、预测、确认、严格/宽松口径分别输出：

- 区域召回率、episode 精确率和未命中区域数；
- 每年误报 episode 数、每区域重复报警数；
- 相对规范锚点的 lead/lag 中位数、四分位数和分布；
- 单峰与多峰区域的分层结果；
- 各指数结果和跨指数汇总，不能只展示成功指数。

明细输出 `region_matches.csv`，聚合输出 `region_metrics.csv`。匹配表保留未匹配区域和未匹配 episode，保证召回率与精确率可复核。

## 四、评测 B：信号后 5/10/20 日结果

这套评测回答“信号之后发生了什么”，不要求信号已匹配顶底区域，也不等同于可交易收益。以信号日收盘价作统计基准，从下一交易日开始观察路径：

```text
terminal_return_h = close[t+h] / close[t] - 1
max_up_h          = max(high[t+1:t+h]) / close[t] - 1
max_down_h        = min(low[t+1:t+h]) / close[t] - 1
```

顶部信号重点报告 `terminal_return`、后续最大下跌和继续上涨风险；底部信号对称报告。5/10/20 日全部保留，60 日不进入新版主评测。

onset 和 capped confirmation 分开统计，以 episode 为主样本；逐日 triggered 结果只作持续信号诊断，避免长 episode 被重复加权。报告样本数、均值、中位数、分位数、相对基准差异和不确定性；重叠期限使用时间序列稳健方法，跨信号/指数多重比较报告 FDR 校正结果。

聚合输出 `forward_metrics.csv`，事件级明细保留在 `forward_event_outcomes.csv`。信号在 `t` 日收盘后才可得，因此上述 close-to-close 数值只表示统计关系，不声称能按 `close[t]` 成交。

## 五、实施顺序与验收

### 阶段 A：冻结协议（已完成）

- 确定 CSV schema、稳定 ID、缺失值和样本尾部规则；
- 参数冻结记录不得包含候选信号成绩。

### 阶段 B：区域标签（已完成）

- 在现有点标签之上新增区域和峰瓣模块，不改写旧 CSV；
- 增加合成 V 顶/底、M 顶、W 底、平台、相邻但应分离区域测试；
- 验收上证 2021 年三个中级顶部均为独立区域：2 月区域为单峰，6 月和 9 月区域为双峰；确认滞后仍为 12、39、88 个交易日。

### 阶段 C：统一事件流与匹配器

- 实现逐日信号/episode schema、onset、exit、capped confirmation；
- 增加给定二进制序列、样本尾部未决、截断不变性和一对一匹配测试；
- 先用合成信号验证预测、确认、重复报警和误报边界。

### 阶段 D：两套报告

- 分别产出区域定位和信号后结果，不生成综合总分；
- 报告顶部/底部、预测/确认、严格/宽松、各指数/汇总切片；
- manifest 固化输入、代码、参数和产物哈希。

### 阶段 E：历史基线与 P1

1. 用新版框架重跑已归档的四行业 Top1，只作为历史基线；
2. 按 [`signal_backlog.md`](signal_backlog.md) 的顺序研究多周期均线宽度、宽度—指数背离、新高—新低广度、涨跌停广度和换手热度；
3. 每个信号先冻结定义，再跑全量结果；不因单个指数或单个区域表现修改阈值。
