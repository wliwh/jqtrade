# JQ 社区策略研究自动化流水线设计

更新日期：2026-08-18<br>
状态：现行设计，尚未完整实现<br>
范围：`strategies/etf_rotation/`、`backtest_executor/` 与 JQ 研究环境

## 1. 目标与边界

把“发现社区策略 → 审计源码 → 参数化 → JQ 试跑 → 参数研究 → 研究报告”改造成可恢复、可追溯、可验证的半自动流水线：

```text
社区发现 → 候选台账 → 源码审计与适配 → 默认参数等价验证
         → JQ 冒烟 → 自适应搜索 → 鲁棒性验证 → Markdown 报告
```

自动化用于减少重复劳动，不用于无人监督地抓取任意代码并批量回测。以下节点必须人工确认：

1. 候选是否值得研究，以及源码是否可用于当前项目；
2. 语义修改是否仍属于原策略；
3. 样本外结论、局限和对外发布文字。

## 2. 当前工程基线

### 2.1 已有能力

`backtest_executor` 已实现参数研究后半段的基础骨架：

- 提取、注入 `EXECUTION_` 参数并计算忽略参数初值的逻辑 hash；
- 通过 `create_backtest()` / `get_backtest()` 提交和轮询 JQ 回测；
- 用 `mapper.json` 去重和恢复，支持 Grid、Random、List、Sensitivity；
- 保存部分 `get_risk()` 指标，并从 `get_period_risks()` 或 `get_results()` 提取年度收益。

尚未形成候选来源追踪、原始源码留存、静态审计、等价验证、完整数据包、自适应搜索、过拟合审计和报告生成的端到端闭环。

### 2.2 自动化前必须加固

下列均为当前代码事实，不代表已修复：

| 风险 | 当前行为 | 目标行为 |
| --- | --- | --- |
| 锚点策略 | `executor.py` 使用模块级 `Default_Back_Id`；YAML `strategy.base_id` 未传入 | 改为可配置 `anchor_algorithm_id`，保留兼容默认值 |
| 实验身份 | 任务 ID 未覆盖逻辑 hash、锚点、基准、信用、Python 和成本 | 完整上下文生成稳定指纹 |
| 策略变更 | 提示删除 `mapper.json` | 新建版本并保留旧实验 |
| 台账损坏 | 解析失败可能静默回到空台账 | 保留损坏文件并明确失败，原子写入 |
| 本地分析 | 取不到 `get_backtest()` 时会生成随机模拟指标 | 正式模式失败；模拟仅可显式启用 |
| 随机搜索 | 可能重复，且无固定种子和反馈 | 提议前去重、可复现、按结果反馈 |
| 结果留存 | 完成后仅保存部分风险指标 | 保存可离线复盘的数据包 |

## 3. 已确认的 JQ 约束

### 3.1 真实锚点策略 ID

JQ 实测表明：即使 `create_backtest()` 传入完整 `code`，仍须提供当前账号可访问的真实 `algorithm_id`。锚点只满足平台创建要求，实际逻辑由 `code` 决定，因此它不能代替策略逻辑身份。

目标配置：

```yaml
jq:
  anchor_algorithm_id: "6e21bbaee8cc3f8423def84436a2bf49"
```

锚点 ID 和 `strategy_logic_hash` 都必须写入实验元数据。Notebook 参数或 YAML 可覆盖锚点，现有真实 `Default_Back_Id` 暂作兼容默认值。

### 3.2 结果接口

采集器按能力探测调用：

- 基础：`get_status()`、`get_params()`、`get_risk()`、`get_results()`、`get_period_risks()`、`get_records()`；
- 晋级候选：`get_orders()`、可能存在的 `get_balances()`；
- 最终候选：`get_positions()`。

公开文档与实际 JQ 环境可能存在版本差异。可选字段缺失时应保存实际字段、采集时间和错误，不得静默推断。参考 [`strategy-api.md`](../reference/joinquant/official/strategy-api.md)。

## 4. 工作流与资产边界

### 4.1 候选状态

```text
discovered → source_saved → reviewed → adapted → preflight_passed
           → smoke_passed → searching → validated → documented
```

失败保留为 `rejected`、`preflight_failed`、`smoke_failed` 或 `search_failed`，并记录阶段、错误摘要、回测 ID、重试次数和更新时间；不能靠覆盖状态或删除文件隐藏。

### 4.2 候选资产

```text
research/<candidate_id>/
├── candidate.yaml       # 来源、作者、URL、评分、状态
├── source/original.py   # 原始源码，只读留存
├── strategy/            # 参数化版与必要的性能优化版
├── changes/             # 可审阅 patch
├── search.yaml          # 参数空间、预算和停止条件
├── runs.json            # 实验台账或索引
├── data/                # 回测数据包
└── report.md            # 研究报告
```

最小追溯信息包括来源与获取时间、各版本源码 hash、语义修改理由、锚点 ID 和实验配置指纹。

### 4.3 模块边界

先形成四个较深模块，不为单个步骤堆浅包装：

| 模块 | 职责 |
| --- | --- |
| 候选工作流 | 来源台账、状态机、原始资产、人工门禁 |
| 策略适配 | 静态审计、参数化、性能优化、等价验证 |
| 实验引擎 | JQ 提交、轮询、恢复、任务身份、参数提议循环 |
| 结果研究 | 数据包采集、鲁棒性、归因、Markdown 输出 |

现有 `executor.py`、`optimize.py`、`analyzer.py` 分别作为实验引擎和结果研究的迁移基础；归档代码只按需提取能力，不重新接回现役入口。

## 5. 阶段门

### 5.1 发现与入库

发现层只生成候选，不根据帖子声称的收益直接决定回测。候选至少记录标题、作者、日期、URL、源码完整性、机制、声称区间和成本口径、依赖及引用来源。

评分关注：

- 机制能否解释、源码能否解析和复现；
- 未来数据、成分回填、幸存者偏差及交易真实性风险；
- 参数是否有明确含义、样本是否覆盖多种市场状态；
- 与现有策略的差异和预计计算成本。

浏览、收藏和回复只帮助发现，不证明策略有效。登录、动态加载或反自动化页面允许浏览器辅助和手工 URL 导入，不以批量抓取为主路径。

### 5.2 审计、适配与等价验证

回测前检查：

- Python/AST、JQ 入口和定时回调是否完整；
- `avoid_future_data` 及数据时间参数是否合理；
- 是否用当前 ETF 列表或行业成分回填历史；
- 成本、滑点、停牌、涨跌停和外部依赖是否明确；
- 是否有循环内重复 JQ 请求、过量日志或无必要的分钟任务。

机械参数化可提取字面量为 `EXECUTION_` 参数、生成 YAML、诊断 `record()` 字段并重新做语法检查。改变选池、评分、风控、交易时刻、成本或数据源均属语义修改，必须人工确认。

性能优化只合并批量查询、缓存同一时点数据、复用指标并减少无业务价值的日志或回调。不得静默关闭未来数据检查、改变执行时刻、删除交易限制或缩短正式区间。

原版和适配版使用相同默认参数、区间及成本比较：完成状态、逐日收益、订单、持仓和关键风险指标。结果有差异时必须解释，不能标作纯性能优化。

### 5.3 JQ 冒烟

新策略不得直接进入参数搜索：

1. 本地语法、参数注入和静态审计通过；
2. 在覆盖实际交易的 3—6 个月执行默认参数回测；
3. 确认状态为 `done`，收益、交易、持仓和风险数据存在；
4. 排除异常空仓、零交易、极端换手和关键 API 缺失；
5. 再执行较长基准回测，通过后才能搜索。

冒烟只证明代码、依赖、交易流程和采集链路跑通，不证明策略有效。

### 5.4 搜索与验证

目标循环：

```text
propose → backtest → collect → evaluate → promote/stop → propose
```

搜索器只提出参数，执行器只可靠运行，分析器只消费已保存数据包。推荐阶段：

1. 去重随机或拉丁超立方做初始覆盖；
2. 用低成本区间淘汰明显不合格参数；
3. 视需要使用贝叶斯优化提议下一组；
4. 在高分区域补邻近参数，寻找平台而非孤点；
5. 少量候选做完整历史和真正独立子区间验证。

综合目标及权重写入配置，至少包含最差区间、跨区间离散度和换手/成本惩罚。停止条件至少支持回测数、总时长、连续无改进、风险门槛和候选重复度。

### 5.5 报告

报告只从可追溯数据生成，至少包含：来源与逻辑、审计结果、版本差异、等价验证、搜索预算、完整与样本外结果、鲁棒性、局限、代码 hash、回测 ID 和数据包索引。帖子声称和临时推测不得写成验证结论。

## 6. 实验身份与持久化

参数 MD5 不足以标识实验。稳定指纹至少覆盖：

```python
execution_context = {
    "strategy_logic_hash": strategy_logic_hash,
    "params": full_params,
    "anchor_algorithm_id": anchor_algorithm_id,
    "start_day": start_day,
    "end_day": end_day,
    "frequency": frequency,
    "initial_cash": initial_cash,
    "benchmark": benchmark,
    "python_version": python_version,
    "use_credit": use_credit,
    "cost_profile": cost_profile,
}
```

逻辑变化时创建新版本，不删除旧 `mapper.json`。跨版本可以查看，但只有代码、区间、成本等口径确认一致时才允许直接比较。台账用临时文件加原子替换；解析失败须保留原文件并报错。

## 7. 回测数据包

| 层级 | 保存内容 |
| --- | --- |
| 全部回测 | 实际参数与配置、状态、风险、累计收益、分期风险、`record()`、字段列表和采集时间 |
| 晋级候选 | 订单；环境支持时保存余额 |
| 最终候选 | 逐日持仓及归因、换仓分析所需行情 |

`get_results().returns` 是累计收益，日收益按 `(1 + cumulative_return).pct_change()` 转换并单独处理首日。

策略按需用 `record()` 保存候选数、入选分数、市场状态、目标换手、过滤原因和实际仓位等内部状态。诊断用于解释参数行为，不能只记录最终收益。

## 8. 鲁棒性与过拟合审计

- 长回测可按年、季度、滚动窗口或市场状态切片，作为低成本筛选；最终候选仍需独立子区间回测，因为预热、持仓和内部状态会跨切片传递。
- 参数平台按“自身得分 + 邻域中位数 − 邻域离散度”评价；收益、持仓和诊断高度相似的参数可聚为同一行为簇。
- PBO 检查样本内优胜者在样本外跌到候选中位数以下的频率；必须保留失败和低分尝试，且不能解释为未来亏损概率。
- DSR 在多次尝试、样本长度、偏度和峰度下修正 Sharpe；有效试验数应根据收益或行为相关性估算，不能直接等于回测组数。
- PBO、DSR 和参数平台都不能替代未来数据审计、合理成交成本、独立留出区间和收益机制判断。

最终候选至少报告分期与滚动收益、最差时期、回撤持续和恢复、尾部风险、参数相关性、交易成本、换手、持仓贡献、换仓效果、市场状态、PBO、DSR 与平台稳定性。

## 9. 自动化边界

可自动完成：候选元数据初筛、源码 hash 与留存、静态审计、机械参数化、冒烟与失败恢复、参数提议与预算控制、数据包采集、统计分析和报告初稿。

不可自动越过：源码使用范围确认、策略语义修改确认、最终研究结论和外部发布。

## 10. 分阶段实施

### P0：加固执行器

- 配置化 `anchor_algorithm_id` 并保留兼容默认值；
- 完善任务指纹和版本化台账；
- 原子写入，禁止损坏台账静默重建；
- 正式模式禁用隐式随机指标；
- 保存基础回测数据包。

### P1：纵向切片

用一个源码完整、逻辑简单的 ETF 策略跑通：

```text
帖子 URL → 原始源码与候选记录 → 审计 → 参数化
        → JQ 默认参数冒烟 → 基础数据包
```

### P2：适配与等价验证

生成参数和 YAML，增加 JQ 调用性能审计，建立收益、订单、持仓一致性检查，保存 patch 与逻辑 hash。

### P3：自适应搜索

实现可复现初始探索、多阶段晋级、预算停止、贝叶斯提议、鲁棒目标和参数平台补点。

### P4：深度分析与文档

完成分层数据采集、PBO/DSR、行为聚类、归因、成本分析和 Markdown 初稿。

### P5：扩大候选发现

P1—P4 跑通后再做批量发现、自动评分和多策略索引，避免先积累大量无法运行或无法相信的源码。

## 11. 验收标准

- 候选可追溯到来源和原始源码，生成版本可解释全部改动；
- 锚点 ID 真实、稳定、可配置，且与逻辑身份分离；
- 参数、逻辑、区间、环境和成本变化不会错误复用旧结果；
- Notebook 中断后可恢复，损坏台账不会静默丢失；
- 冒烟失败不会进入搜索，搜索能减少重复和低价值回测；
- 最终候选来自稳定参数区域，并有独立区间和过拟合审计；
- 所有指标和结论可回溯到数据包与 JQ 回测 ID；
- 文档明确区分事实、推断、局限和未验证事项。
