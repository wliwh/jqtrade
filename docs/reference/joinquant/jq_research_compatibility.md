# JQ 目标程序运行时兼容性

本文是项目内所有 **目标平台为 JQ 投资研究、JQ 回测或模拟盘** 的程序的强制约束。包括直接复制到 Notebook 的研究脚本、`adapters/jq/` 导出程序、`strategies/` 策略源码，以及通过 `create_backtest()` 注入 JQ 的代码。纯本地分析模块不必退回旧语法，但它与 JQ 共用的文件和数据边界必须显式分开。

## 已验证的运行时基线

- 本项目最近实测的 JQ 环境使用 Python 3.6、旧 pandas 和 `from jqdata import *`。未在平台重新核验并更新本文前，JQ 目标文件必须保持 Python 3.6 兼容。
- JQ 目标文件不使用 `from __future__ import annotations`、海象运算符、`dataclasses` 等 Python 3.6 之后才可用的语言或标准库能力。
- 不把本地 `jqdatasdk` 的导入、认证、返回形状或文件系统行为混入 JQ 平台程序。需要兼顾本地测试时，只允许在模块顶层用 `try: from jqdata import *` 建立平台边界，本地测试注入假 API。
- `from jqdata import *` 可能向模块全局注入 `any`、`min`、`max`、`sum` 等 Python 内置同名对象。JQ 目标文件必须在导入边界后统一恢复实际使用的 Python 内置名，或在调用处显式使用 `builtins.<name>`；不得依赖未保护的内置名。
- `jqdata` 导入成功不等于平台 API 一定出现在 `globals()` 返回的模块字典中；Notebook 或回测入口还可能通过 Python builtins 注入 API。平台程序应直接使用正常的 Python 名称解析，或在可测试的适配边界依次检查模块全局与 builtins，不得只用 `globals().get(...)` 判定 `get_price`、`get_industries` 等 API 不可用。
- 不使用旧 pandas 缺失或语义不同的接口，包括 `Series.to_numpy(dtype=...)`、nullable boolean、`pd.NA`、`groupby(dropna=False)` 和 `to_csv(lineterminator=...)`；使用 `.values`、`numpy.nan`、普通 `bool`、基础 `groupby` 和旧版支持的 `to_csv` 参数。

## 数据与时间边界

- 所有日期参数显式传入。研究环境中部分 API 的默认日期是“今天”，回测中则可能随 `context.current_dt` 变化；不得依赖这种差异形成隐式时点。
- `get_price(..., panel=False)` 的多标的结果按 JQ 实际返回的长表或 MultiIndex 形状规范化；本地构造的宽表不能证明平台返回兼容。
- 研究脚本的日期 `t` 信号只能使用 `t` 当时已知的数据。用 `close[t]` 定义未来结果时，必须声明它是研究参考价而非可成交价。
- 当前列表、当前行业或当前 ETF 不能静默回填历史。需要历史成分或行业时，显式传入日期，或使用本身带日期和历史代码的官方表。
- `finance.run_query` 单次最多返回 5000 行。预估结果可能超限时，必须按标的或时间分批，并检查每批行数、首尾日期、重复键和缺失标的。

## 资源与输出

- 先用约一个月或能覆盖至少一次有效事件/交易的短区间跑完整流程，再运行正式区间；短区间必须经过与正式区间相同的计算和输出路径。
- 批量行情优先一次取多个标的，但要控制矩阵规模；超大股票池按稳定批次处理，不在逐日循环中重复请求整段历史。
- JQ 回测/模拟盘的策略进程不能依赖普通本地文件写入；使用平台提供的 `read_file` / `write_file`，或把研究 Notebook 的本地 CSV/ZIP 输出明确限制在投资研究环境。
- 输出至少记录程序路径或 Notebook 版本、逻辑 hash、参数、实际数据起止日、平台 Python/pandas 版本和运行日期。策略比较还必须记录成本、频率、锚点策略 ID 和 JQ 回测 ID。
- 同名历史快照和既有回测台账不可覆盖。口径、代码或日期改变时升级版本，并保留失败结果和 traceback。

## 必做预检与冒烟

1. 本地检查 JQ 目标文件不存在 Python 3.6/旧 pandas 禁用项，运行语法检查和确定性单元测试。
2. 在 JQ 打印并保存 `sys.version`、`pd.__version__`，同时冒烟关键 API 的真实返回列、索引和行数。
3. 用短区间执行完整入口，确认不是空数据、零有效截面、零交易或仅生成表头；检查输出中的实际覆盖和缺失原因。
4. 修改函数后重新执行完整定义单元或重启内核，避免 Notebook 沿用旧函数对象。
5. 正式运行后保存平台输出及协议偏离；本地测试不能替代 JQ 数据覆盖、资源限制、撮合语义或真实运行结果。
